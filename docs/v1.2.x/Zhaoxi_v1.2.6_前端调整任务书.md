# Zhaoxi v1.2.6 前端调整任务书

## 版本主题

**Agenda 时间线 + Short-Term Memory 便利签展示重构**

> 本任务书只处理前端展示与交互。
> Short-Term Memory 后端已单独重构，不在本任务中重新设计其维护逻辑。

---

# 一、改动背景

当前 v1.2.6 前端存在两个明显偏差：

1. **Agenda 被做成了普通卡片列表**
   - 时间先后关系不直观
   - Event / Window / Deadline / Focus / Expectation 之间的差异弱
   - 视觉上更像“任务流”，而不是“近期时间流”

2. **Working Notes 被做成了可为空的便签列表**
   - 但后端语义已经调整为 **Short-Term Memory**
   - 它不是偶尔出现的 TODO / Note
   - 而是朝汐对“最近数天至约一周正在发生什么”的持续滚动概要
   - 前端应表现为一张长期存在的“近期状态便利签”

因此本轮前端目标是：

> **让 Agenda 一眼看出时间推进，让 Short-Term Memory 一眼看出最近整体状态。**

---

# 二、总体布局

保持现有“小桌边”入口，但重构其中两块核心区域：

```text
┌──────────────────────────────┐
│ 日程表 · Agenda              │
│                              │
│   09/24                      │
│    ● 13:00 AI+创新产业大会   │
│    │                         │
│   09/26                      │
│    ◆ 14:00 线下纯 K 活动     │
│    │                         │
│    ▲ 09/28 网申截止          │
│                              │
├──────────────────────────────┤
│ 近期状态 · Short-Term Memory │
│                              │
│  最近仍主要处于秋招阶段……     │
│                              │
│  当前持续：                  │
│  · 秋招与岗位筛选            │
│  · Zhaoxi v1.2.6 开发        │
│                              │
│  最近变化：                  │
│  · Agenda 改为时间线展示      │
└──────────────────────────────┘
```

两个模块都应保持：

- 轻量
- 高信息密度
- 不像后台管理系统
- 不像 Jira / Todo App
- 更像“桌边摊开的日程簿 + 一张便利贴”

---

# 三、Agenda 改为纵向时间线

## 3.1 核心要求

彻底放弃当前“每条事项一个大卡片”的主展示方式。

Agenda 主视图改为：

> **纵向 Timeline**

强调：

- 时间顺序
- 日期分组
- 类型差异
- 当前 / 未来位置关系

---

# 四、时间线基础结构

推荐布局：

```text
09/24 周四

● 13:00
│  AI+创新产业大会（观众）
│  约定
│
│
09/26 周六

◆ 14:00
│  和 gal 社群朋友参加线下纯 K 活动
│  时间窗口
│
│
▲ 23:59
   某网申截止
   Deadline
```

要求：

- 左侧为时间线主轴
- 每个事项挂在时间线上
- 日期作为明显分组节点
- 同一天多个事项按时间排序
- 不再用整块厚重卡片切断时间流

---

# 五、Agenda 类型节点

五类 Agenda 使用不同节点视觉。

建议：

```text
● Event / 约定
◆ Window / 时间窗口
▲ Deadline / 截止
■ Focus / 主线
○ Expectation / 有余力再做
```

不强制使用这些具体符号，但必须做到：

> 用户不看文字标签，也能大致分辨事项类型。

可以通过：

- 节点形状
- 线型
- 小图标
- 浅色底纹
- 标签样式

进行区分。

不要只依赖颜色，避免可读性过度依赖色差。

---

# 六、Agenda 信息层级

单个节点只保留高价值信息。

推荐三层：

```text
13:00
AI+创新产业大会（观众）
约定
```

如果有 Note，可作为次要信息展开：

```text
13:00
AI+创新产业大会（观众）
约定

观众身份参加，提前确认路线
```

默认不要展示大量数据库字段。

隐藏：

- id
- source
- created_at
- updated_at
- 内部状态字段
- 其他实现信息

---

# 七、日期分组

Agenda 优先按日期分组。

例如：

```text
今天 · 09/24

明天 · 09/25

09/26 周六

09/28 周一
```

推荐对：

- 今天
- 明天

提供自然语言强化。

超过近期范围后直接使用日期。

不要所有项目都只显示完整时间戳。

---

# 八、当前时间位置

如果当天存在多项 Agenda，建议提供轻量的“现在”指示。

例如：

```text
09:00
● ...

12:30
──────── 现在 ────────

13:00
● ...
```

目的：

> 一眼看出已经过去什么，下一件事情是什么。

不要做得像复杂甘特图。

---

# 九、过去事项处理

已经结束的 Event / Window 不应与未来事项同权重。

推荐：

- 轻微降低视觉权重
- 标记完成的可显示 ✓
- Missed 可以保留很轻的提示
- 默认重点始终落在“现在之后”

例如：

```text
✓ 10:00 上午宣讲

──────── 现在 ────────

● 14:30 线下面试
```

不要让大量历史事项占满页面。

---

# 十、Mainline / Focus 的展示

Focus 不适合完全按照 Event 的方式挂在某个精确时间点。

推荐两种方案之一：

## 方案 A：当天时间线顶部

```text
今日主线
■ 秋招活动 + 项目案例整理
```

之后再进入具体时间线。

## 方案 B：作为整日节点

```text
09/24 周四

■ 今日主线
  秋招活动 + 项目案例整理

● 13:00
  AI+创新产业大会
```

优先保证：

> Focus 看起来是当天方向，而不是“13:00 的一个任务”。

---

# 十一、Expectation 展示

Expectation 应明显弱于 Event / Deadline。

例如：

```text
○ 今晚有精力
  Life HUD README
```

视觉上使用：

- 更轻的节点
- 更浅的文本层级
- 不强调警告
- 不产生“没完成就是失败”的压迫感

---

# 十二、Deadline 展示

Deadline 必须比普通 Window 更容易被看到。

例如：

```text
▲ 09/28 23:59
  网申截止
```

接近 Deadline 时可以通过前端轻微增强权重。

但本轮不实现主动提醒逻辑。

这里只做展示。

---

# 十三、Agenda 重复项视觉处理

当前截图中存在类似：

```text
AI+创新产业大会（观众）
```

和：

```text
作为观众参加 AI+创新产业大会
```

视觉上高度重复。

前端应避免同一件事情看起来像两条完全独立的事项。

优先策略：

1. 后端若已有关联关系，按关联关系层级展示
2. 无关联信息时，前端不要擅自删除数据
3. 但可减少重复标题造成的视觉噪音

例如：

```text
● 13:00 AI+创新产业大会
  观众
```

而不是：

```text
AI+创新产业大会（观众）

作为观众参加 AI+创新产业大会
```

如果无法可靠判断是否同一事项，则保持数据完整，不做危险合并。

---

# 十四、Short-Term Memory 前端重新定位

原 Working Notes 区域不再表现为：

> “有没有正在整理的便签”

而改为：

> **朝汐近期状态便利签**

建议前端标题改为：

```text
近期状态 · Short-Term Memory
```

或：

```text
朝汐便签 · Short-Term Memory
```

具体名称允许根据现有 UI 风格选择。

---

# 十五、Short-Term Memory 必须默认有内容

正常使用后，不再出现：

```text
眼下没有正在整理的便签。
```

这类旧 Working Notes 空状态。

Short-Term Memory 本身就是：

> 最近数天至约一周的滚动概要。

只要后端已有 STM Snapshot，前端就直接展示。

真正首次初始化、完全无数据时，才允许：

```text
近期状态正在形成中。
```

---

# 十六、Short-Term Memory 展示方式

不要重新做成一堆 Note Card。

推荐：

> 一张较大的整体便利贴 / 状态板。

例如：

```text
近期状态

暗苟最近仍主要处于秋招阶段，同时持续推进
Zhaoxi 开发。近期动漫与角色绘图相关聊天有所增加。

当前持续
· 秋招与岗位筛选
· Zhaoxi v1.2.6

最近变化
· Working Notes 已重构为短期记忆
· Agenda 计划改为时间线
```

它应该看起来像：

> 一张不断被朝汐擦写更新的纸。

不是：

> 数据库里 8 条记录的展示器。

---

# 十七、Short-Term Memory 信息层级

建议优先展示：

## 1. Overview

顶部放自然语言概要。

这是整块内容最重要的部分。

例如：

```text
暗苟最近仍主要处于秋招阶段，同时持续推进 Zhaoxi。
最近动漫、角色和绘图相关话题有所增加。
```

## 2. Active Context / Threads

如果后端提供：

```text
active_contexts
active_threads
```

可显示为：

```text
当前持续
· 秋招与岗位筛选
· Zhaoxi v1.2.6
```

## 3. Recent Changes

例如：

```text
最近变化
· Short-Term Memory 完成后端重构
· Agenda 前端准备改为时间线
```

## 4. Unresolved

如果存在：

```text
还挂着
· Agenda Timeline 前端尚未完成
```

没有该类数据时整个区块隐藏。

---

# 十八、不要强行把所有字段都展示

后端可能提供：

```text
overview
active_contexts
active_threads
recent_topics
recent_changes
unresolved_context
```

前端不要机械六块全铺出来。

原则：

> 先看起来像一个自然状态概要，再考虑字段完整性。

如果某部分为空：

直接隐藏。

不要显示：

```text
Recent Topics:
暂无

Unresolved:
暂无
```

避免后台 Dashboard 味。

---

# 十九、Recent Topics 的展示

如果近期话题存在，可以轻量展示：

```text
最近常聊
动漫 · 角色绘图 · 秋招
```

推荐：

- 小型 tag
- 行内文字
- 轻量胶囊

不要每个 Topic 做一张卡。

---

# 二十、更新时间

Short-Term Memory 可以在角落弱化显示：

```text
刚刚更新
```

或：

```text
23:21 更新
```

不要突出完整数据库时间戳。

例如不要：

```text
updated_at: 2026-09-23T23:21:42+08:00
```

---

# 二十一、便利贴视觉

Short-Term Memory 可以继续保留“便利签”隐喻。

建议：

- 比 Agenda 更松弛
- 有轻微纸张感
- 可使用现有胶带元素
- 文本左对齐
- 不使用密集分隔线
- 不使用表格
- 不使用大量按钮

核心观感：

> 朝汐在桌边留下的一页近期摘要。

---

# 二十二、Agenda 与 STM 的视觉关系

两者要有明显不同的性格：

```text
Agenda
→ 有秩序
→ 线性
→ 精确
→ 时间轴

Short-Term Memory
→ 柔和
→ 概要
→ 连续
→ 便利贴
```

不要两块最终又长成同一种卡片列表。

---

# 二十三、“小桌边”入口调整

当前右侧“小桌边”入口插在滚动区域中间，视觉上比较割裂。

建议改为以下之一：

## 优先方案

放到容器右上角，作为固定入口：

```text
日程表 · Agenda               [小桌边]
```

## 或

作为顶部 Tab：

```text
[聊天] [小桌边]
```

## 或

做成侧边固定的小型把手，但不要压住内容滚动区域。

目标：

> 入口存在感可以有，但不能把时间线切断。

---

# 二十四、滚动行为

当前 Agenda 区域内部有较明显独立滚动条。

如果页面整体空间允许，优先：

- 整个“小桌边”面板统一滚动

而不是：

```text
Agenda 自己滚
STM 又在下面
```

导致用户必须先滚一个内部容器，再滚外层。

如果必须保留内部滚动：

- 滚动条弱化
- 不遮挡 Timeline
- Timeline 主轴不要贴滚动条

---

# 二十五、响应式

至少检查：

```text
窄窗口
普通桌面窗口
较高分辨率桌面
```

重点：

- Timeline 不被压扁
- 时间列不换行得很难看
- Short-Term Memory 段落保持合理行宽
- “小桌边”入口不遮挡内容
- 日期标题不和节点重叠

---

# 二十六、交互要求

本轮前端优先展示，不做复杂编辑系统。

如果当前已有编辑功能，可保留。

但不要为了 Timeline 新增大量：

```text
拖拽改时间
鼠标排序
复杂右键菜单
日历弹窗
```

当前主要目标：

> 看得懂，扫一眼就知道最近发生什么。

---

# 二十七、推荐组件拆分

根据现有框架调整，语义上建议：

```text
AgendaPanel
├── AgendaDateGroup
├── AgendaTimeline
├── AgendaTimelineItem
├── AgendaNowMarker
└── AgendaFocusBlock

ShortTermMemoryPanel
├── ShortTermOverview
├── ActiveThreads
├── RecentTopics
├── RecentChanges
└── UnresolvedContext
```

不要做成一个几百行的大组件。

---

# 二十八、兼容后端新模型

前端需要从旧：

```text
Working Notes[]
```

切换到新的：

```text
ShortTermMemory Snapshot / State
```

确认：

- 不再依赖旧 Note CRUD 数据结构
- 不再判断 `notes.length === 0`
- 不再使用“没有正在整理的便签”作为常态逻辑
- 不再显示旧 WorkingNote 类型标签
- 不再依赖 resolved / active note 分组

需要根据实际后端 API / IPC 返回结构进行适配。

---

# 二十九、容错

如果 STM API 暂时不可用：

```text
近期状态暂时无法读取
```

即可。

不要导致整个小桌边崩溃。

Agenda 同理。

两个模块应独立容错。

---

# 三十、加载状态

不要使用巨大的 Loading Spinner。

推荐：

```text
近期状态整理中…
```

或者轻量 Skeleton。

Agenda：

```text
正在翻日程…
```

保持整体氛围轻。

---

# 三十一、本轮不做

明确排除：

```text
Agenda 后端重构
Short-Term Memory 后端维护逻辑
Decision System
主动提醒
拖拽排期
完整日历
周视图 / 月视图
Google Calendar 同步
复杂动画
复杂编辑器
新的 Note CRUD
长期 Memory 展示
```

不要再次扩大范围。

# 三十二、验收场景 A：Agenda Timeline

数据：

```text
09/24 13:00 Event
09/26 14:00 Window
09/28 23:59 Deadline
```

前端应：

- 按日期排序
- 形成连续纵向时间线
- 三类节点视觉可区分
- 不再显示成三张厚重独立卡片

---

# 三十三、验收场景 B：今日主线

数据：

```text
Focus:
今日主线：完成 Zhaoxi v1.2.6
```

前端应明显显示：

```text
今日主线
完成 Zhaoxi v1.2.6
```

而不是把它伪装成某个具体时间点 Event。

---

# 三十四、验收场景 C：当前时间

今天：

```text
10:00 Event A
14:00 Event B
```

当前：

```text
12:30
```

前端能够自然看出：

```text
Event A 已过去

—— 现在 ——

Event B 即将到来
```

---

# 三十五、验收场景 D：Short-Term Memory

后端返回：

```text
overview:
暗苟近期主要处于秋招阶段，同时持续开发 Zhaoxi。

active_threads:
- 秋招与岗位筛选
- Zhaoxi v1.2.6

recent_topics:
- 动漫
- 角色绘图
```

前端应呈现为一张完整状态便利贴。

不能呈现为：

```text
3 张独立 Note Card
```

---

# 三十六、验收场景 E：STM 部分字段为空

只有：

```text
overview
active_threads
```

则只显示这两部分。

不要额外出现：

```text
最近变化：暂无
未解决：暂无
最近话题：暂无
```

---

# 三十七、验收场景 F：首次初始化

STM 后端尚未形成状态。

允许：

```text
近期状态正在形成中。
```

但不得继续出现旧文案：

```text
眼下没有正在整理的便签。
```

---

# 三十八、整体视觉验收

最终页面第一眼应该传达：

```text
上面：
“接下来什么时候有什么”

下面：
“最近这一阵子是什么状态”
```

而不是：

```text
上面：
一堆任务卡

下面：
一个空的 Note Box
```

---

# 三十九、最终完成标准

本轮完成应满足：

- Agenda 主视图已经改为纵向 Timeline
- Agenda 按日期自然分组
- Event / Window / Deadline / Focus / Expectation 视觉上可区分
- 当前时间位置能够自然表达
- 已过去事项弱化
- Focus 不再被误当成普通定时事项
- Expectation 保持低压力视觉
- Short-Term Memory 替代旧 Working Notes 展示模型
- STM 默认展示整体近期概要
- STM 不再以 Notes 列表为核心
- STM 空字段自动隐藏
- 旧 Working Notes 空状态文案已删除
- “小桌边”入口不再遮挡主要内容
- 滚动体验自然
- 窄窗口下布局不破坏
- Agenda 与 STM 各自独立容错
- 不修改本轮已经完成的 STM 后端逻辑
- 不新增范围外功能

---

# 四十、版本视觉目标

> **Agenda 是一条向前延伸的时间线。**

> **Short-Term Memory 是朝汐一直放在桌边、不断擦写更新的那张便利贴。**

最终用户打开“小桌边”时，不需要阅读后台字段，也不需要研究任务列表。

应该只需要扫一眼，就知道：

```text
现在是什么时候
接下来有什么
最近我们在经历什么
```
