# v1.2.9 Decision Layer 开发记录

日期：2026-09-25。依据 [开发任务书](<Zhaoxi_v1.2.9_Decision Layer_Task.md>)、`data/archive/zhaoxi/先声 v0.1.md` 与 `data/archive/user/决策协议 v1.0.md`。运行时版本号维持原值；本记录是功能开发结果，不代表正式发布。

## 已实现

- 自然语言入口仅在明确决策意图，或认知路由进入有多个方向的规划时触发 Decision Service。普通闲聊不增加一次决策模型调用。用户覆盖建议优先于路由处理。
- Decision Context 限量读取今日主线、日程、Current Cognition、相关长期记忆、少量结构化规则与当前可用工具名称；不会注入整份协议或完整聊天记录。
- 可编辑 JSON 规则放在 `data/decisions/rules/`。规则按领域、标签、关键词和必要的触发证据检索，单次最多五条。首批规则取自协议与先声，包含岗位硬底线、今日主线、可逆低成本选择及长期职业方向。
- 结构化分类与表达分离。Guard 对长期影响、正式 Offer、冲突、信息缺失、判断不稳和未知副作用上调层级。L0 必须引用明确规则。L2 清除模型给出的结论；“替我决定”也不能压低 L2。工具自动执行同时要求规则与 Tool manifest 授权，现有首批规则均未授予自动工具执行。
- L0/L1 `DecisionResult.verdict` 必须给出方向性陈述，疑问句会触发一次重新判定；仍无方向时升为 L2。Decision Layer 不生成聊天回复。朝汐主回复链读取 Persona 并选择表达语气和已确认理由，运行时锁定 verdict，忽略主模型额外生成、可能推翻决定的自由文本。
- 决策与人工覆盖以 JSONL 保存在 `.zhaoxi/decisions/`，并纳入备份清单。日志使用结构化摘要。相同规则被覆盖三次后只生成 `RuleCandidate`，不会改写正式规则。
- Debug 提供最近决策、上下文、规则来源、升级理由、自动执行判断、规则候选，以及独立的测试重算和测试层级。测试重算不写日志，也不覆盖正在进行的会话状态。

## 当前边界

- 首批规则不授权自动工具执行，因此 L0 目前只给出短结论；后续若增加明确允许的可逆低风险规则，需要把 `can_auto_execute` 接到受 Tool Permission 约束的执行路径，再按真实工具行为验收。
- 规则失效检测当前覆盖重复人工覆盖；长期效果与现实前提变化需要有结果或事实更新记录后才能可靠判断。
- 分类输出仍取决于模型对事实的理解；守卫覆盖高影响、缺失信息、规则冲突等可确定的安全边界，无法以关键词代替全部价值判断。
