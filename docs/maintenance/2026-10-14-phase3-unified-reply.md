# Phase3 统一回复候选实现与真实证据

日期：2026-10-14。对应 [Phase3 开发任务书](../v1.4.x/Zhaoxi_v1.4.9_Phase3_Cognitive_Faculty_Layer_开发任务书.md)。状态：P3-01～P3-03 的候选接线已实现，P3-04 日用验收待正式 Core 加载后开始；不宣称已达到 98% 或已删除 FAST。

## 本轮实现

- `unified_reply_enabled` 默认开启，仅在 agency 模式启用新路径。Desktop/Web、QQ 的正文都复用现有 Agent Loop；普通请求跳过 Router 模型调用与 FAST，原有明确能力提示、预挂载和工具权限继续生效。QQ 仍不使用 Planner，真人定向回复和防 bot 互答规则保留。
- 普通正文只要求 `{"reply":"正文"}`；能力准备统一使用可选 `escalation`，校验类型、当前输入引用、实际能力组和频道权限。决策资料按需激活，真正新选择仍须提供 mode、decision_kind、decision_question 和建议；公开频道不能读取私人资料。
- 正文无效时最多一次纯正文补写，共享原请求预算，保留实际回执、有限近期上下文、引用和频道边界。补写不开放业务工具；必要保存失败保留正文、给出保存失败提示并标记部分成功。状态也随直接调用返回，不依赖遥测开关才成立。被拒绝的能力请求可以补写限制说明，避免 QQ 直接无声退出。
- 默认不常驻完整 Decision Guidance、全量 Tool Domain Map 和持久工具 Schema；工具行动的说明仅在实际需要时提供。完整表情组合保持可用，提示文字精简；行动后的 Decision 收口也使用短提示。没有通过置空服务关闭后台记忆形成。
- 同源、同参数的 Decision 查询在当前回合复用，写入会清除读取缓存。显式 Memory 查询与关联检索的过滤和语义不同，不强行合并它们。
- 新选择以真实源消息和 scope 生成稳定 ID；已有同源旧 ID 继续复用。同一反馈源消息重试不重复追加，包括仅更新最终选择、没有结果标签的反馈。
- 近期时间线先在数据库按时间筛选，再加载媒体；真实副本的 27 条近期事件与原算法一致，保留原时间、来源与可见性过滤，未缩小原有 8 单元 / 3000 字符普通窗口和视觉窗口。
- 记录 Core/前端源码构建指纹、运行配置指纹、当前能力明细、入口、页面渲染与 QQ 投递确认。配置指纹包含实际思考模式、调试轮次和工具覆盖配置。明细已经包含在原八类中，不重复累加 Token。

## 真实材料与测量边界

本轮首次旧正式日志只读审计捕获 436 个入口请求：390 个旧终态标记 completed，33 failed、12 partial_success、1 budget_exhausted；它们跨旧构建与配置，没有可用构建标识，也没有本轮新增的交付确认日志。390 是“旧终态标记完成”，不是已证明的端到端成功；确认覆盖为 0，不能把它解释成实际失败率 100%。

本地使用正式 Session、Experience、Current Cognition 和 Choice History 的 SQLite/文件副本，以及当前人格与表情资料，在实际 Agent Loop 的 Provider 入口截取输入，停止于推理之前。8 条真实已保存普通请求的文本载荷合计由 FAST 的 102,639 字符降为统一路径的 71,610 字符，减少约 30.23%；本地组装 P95 为 225.64ms。保持相同人格、表情组合、近期窗口和图像预算。

该测量使用相同的最小本地 Registry，不覆盖生产所有插件或手动强制挂载；只有输入组装，没有模型输出、API Token、语义正确率或网络端到端性能证据。不能用字符减少代替实际 Token 达标，也不能用这 8 条代替 7 天 / 500 次自然日用观察。

素材和详细诊断留在忽略目录 `.pytest_cache/phase3/`，没有外发私人内容、调用模型、发送 QQ、修改生产数据库或重启正式实例。旧选择副本中没有满足本轮“抽象问题 + 可用源消息 ID”条件的记录，未编造来源做幂等验收；新记录的真实回访与重生成还需日用样本。

## 指标读取与验收

只读运行：

```powershell
.venv/Scripts/python.exe scripts/phase3_reliability_audit.py --output .pytest_cache/phase3/live-audit.json
```

审计按 build_id 和 configuration_id 分组；入口已经接受却没有终态回执的请求，到期后仍留在分母。未到期的请求单列 pending。重复渠道事件不覆盖原终态；手动重生成使用原 source_request_id 追踪，单列恢复，不增加原请求成功样本。权限提示的正确交付与业务完成分别统计，不将等待授权当作动作完成。

当前窗口同时报告运行终态、交付证据覆盖、确认完成下界、首次回复阶段、正文补写成本、调用次数、渠道、任务类型及时间 P95。候选窗口需满足已知构建与配置、统一路径、7 天、500 次和整体/最近窗口要求；即使交付窗口满足，release_acceptance 仍为 pending_business_review，需要检查必要持久化、语义错误、关键路径样本、实际 Token 和匹配性能。

工程回归用于保护协议、恢复、权限、幂等与界面接线；不将测试数量或模拟回包作为真实成功率验收。原 QQ 检查中“Planner 可拒绝定向回复”“真人冷却拦截”等断言已按用户先前确认的策略更新；bot 互答检查保留。
