# FAST_CHAT 工具冲突修复记录

日期：2026-10-06。用户在 [调试开关与修复方案](2026-10-05-fast-chat-debug-and-repair-plan.md) 后授权实施。此记录说明源码修复与隔离验收；没有重启正式实例、修改实际界面设置、调用真实模型或发送外部消息。

## 修复结果

FAST 升级继续使用现有 STANDARD 循环，默认模型 3 轮、业务工具 2 轮，最多补偿 1 轮真正扩展能力且尚未执行业务的工具发现。取消原先 FAST 升级专用的 2/1/0 缩减。最后一轮用于整理结果；即使发现补偿增加了模型额度，总步数的最后一步也禁止启动新操作。FAST 草稿仍丢弃，升级后不再进入 FAST 或 Router，原有模型调用数、Token、总步数、权限和失败保护继续约束整次请求。

这覆盖了日志中的第一处失败：只发现工具就耗尽有效执行机会。验收包含「FAST → 发现工具 → 读取 ID → 请求写入确认 → 写入一次 → 回复」；确认前没有写入，确认后没有重复读取或写入。两个 Debug 开关都保持默认关闭，正常模式即可完成此链路。

要求工具但没有执行时，结果状态改为 `failed`，发出 `required_tool_not_executed` 并返回明确未执行说明。模型未经核验的完成声明不会继续交付。工具成功与未完成步骤并存时，任务为 `partial`、结果为 `partial_success`；已成功动作仍逐项保留。最终回复生成失败与业务执行失败仍分开处理，已完成操作不会因回复预算耗尽被改成失败。

Desktop 和 Dashboard 共用的行动记录摘要现在保留「未完成」「部分完成」，不会因为稍后的回复交付或 `runtime_finished: success` 覆盖为「已完成」。前端构建标识更新为 `v1.4.7-fast-tool-repair-20261006`。

## 明确重试

为**尚未执行业务工具**、且执行入口原本要求工具的失败保存一条内存上下文，包含请求 ID、原始请求、Owner/频道/会话/会话目标及创建时间。模型在闲聊中自己承诺查询，不会因此产生可重试任务。

后续明确说「再试一次」「请重试一下」时，只有身份、频道、会话与目标相同且未过五分钟，才直接转入 STANDARD 处理原始请求，绕开 FAST 的当前动作关键词限制。记录在下一轮判断时即消费；无关消息、取消、引用、扩大动作范围、图片、待确认操作或来源变化都不能恢复它。Owner 切换到外部频道时也清空本地记录。

恢复只提供原始任务意图，不复用旧草稿工具参数，不伪造新的历史 User 消息，不绕过写入确认。已成功执行、结果未知、权限拒绝和已尝试过的失败写入均不会产生可自动恢复的上下文。重启 Core 后这条临时上下文自然丢弃。

此实现选择比早期方案更保守的范围：**已经尝试执行的工具失败，包括只读失败，暂不通过短句自动恢复**。此类重试仍需重新明确描述操作。当前日志中第二处失败没有任何业务工具执行，属于已实现范围。这里没有引入失败任务库或持久化重放队列。

## 修改位置

- `core/agent.py`、`core/loop_safety.py`：统一执行额度、收口步数、真实结果与未执行上下文。
- `core/tool_retry.py`、`core/runtime.py`：单条短期上下文与当前来源绑定。
- `cognitive/coordinator.py`、`interfaces/gateway.py`、`perception/runtime.py`：经过认证的本地范围、直接恢复与频道切换失效。
- `observability.py`、共享 `web/static/shell.js`：未执行/部分完成的任务、日志与双端摘要一致。
- `core/fast_chat.py`：将仅验证时需要的 FAST Gate 辅助函数导入延后，消除独立导入 FAST Runtime 时的循环依赖。

原有 Debug 开关、即时保存、SSE 同步、互斥与启动恢复均保留。运行中的请求保持已有安全额度；新请求使用修复后的默认标准额度。

## 验收

命令、结果与隔离浏览器检查列表见 [结构化证据](evidence/2026-10-06-fast-chat-tool-repair.json)。

- 后端专项：279 项通过；包含工具发现、读取后确认写入、恰好一次、未执行状态、原始任务恢复、写入确认、过期/取消/引用/范围改变、身份/会话/频道隔离、公开频道不借用本地身份、预算与无进展保护。
- 前端 Node：96 项通过；新增解释回复成功后仍保留失败/部分状态的行为检查。
- Edge 双端：15 项检查通过，含 Desktop、Dashboard 设置/运行页，开关同步与持久化、互斥、失败与部分完成摘要；没有页面脚本错误。使用系统临时状态、假模型和 mock 主动请求，独立服务已退出。
- Core 完整运行：1343 项通过、1 项跳过，1 项工具发现测试已加载旧回复预期而失败。修正后失败项单独复验通过；最后的 279 项专项包含该测试、新增公开来源检查和最终频道切换修改，没有重复整套慢测试。
- Python 语法：432 个文件通过；`git diff --check` 通过。现有 Starlette/httpx 弃用提示仍存在，没有修改依赖。

测试过程中发现两类旧预期需要调整：原来要求 FAST 升级更小额度的断言，以及把未执行草稿或部分任务视为完成的断言。针对性测试还修正了确认请求缺少 request_id、事件订阅方式和提前收口的调用计数。首次独立收集暴露 FAST Runtime 的循环导入，已修复；预算耗尽后保留成功动作的既有回归也保持通过。以上尝试会保留在结构化证据，不以失败的中间结果替代最终验收。

## 使用与边界

加载 Python 源码修复需从托盘完全退出朝汐后重新启动，并刷新 Web/Desktop 页面；侧边栏的进程内“重启 Core”不会重新加载源码。详见后续 [快速入口启动排查记录](2026-10-06-desktop-startup-recovery.md)。本次没有执行正式重启，也没有开启生产 Debug 设置；正常使用不必开启两个新开关。若同一任务尚未执行，可在当前会话五分钟内明确要求重试；换资源、换动作或已有未知结果时，请明确描述新请求，继续使用原有确认流程。

未做真实模型联网验收；模型选择工具的稳定性与正式插件返回值仍需加载新代码后观察。此前独立的 Perception 输入超过快照预算问题没有纳入本修复。
