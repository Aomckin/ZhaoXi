# 主动消息与戳一戳被残留勿扰信号截断

记录日期：2026-10-14。状态：源码已修复，真实日志已在本地复盘；正在运行的 Core 尚未重启加载，实际投递恢复待观察。

## 真实证据与根因

- 2026-10-13 21:57:48 开启桌面勿扰，22:04:03 关闭。
- 关闭以后仍有 11 次强制 Beat 记录为 `gate_reason=blocked`、`forced=true`、`llm_called=false`；其中包括 2026-10-14 00:01:59 和 00:03:44。
- 心跳将勿扰状态投影为 `interruptibility.manual / quiet_mode` 信号。桌面无限期勿扰使信号过期时间变成 `datetime.max`，关闭勿扰仅清空 `PolicyState.quiet_until`，没有撤销已投影的信号。
- 普通 Beat 被残留信号拦截；戳一戳虽然绕过 `quiet_until` 检查，却没有绕过同一勿扰状态生成的信号，调用模型前就返回。

## 修复

1. 信号聚合器支持按类型与来源撤销信号。心跳在勿扰关闭或到期时，仅移除 `quiet_mode` 来源的手动打扰信号。
2. Beat 在检查当前勿扰状态时也清除过期投影，避免托盘关闭勿扰后、下一次心跳之前仍拦截已排队的决策。
3. 强制戳一戳在决策前和实际投递前均忽略 `quiet_mode` 信号；勿扰设置本身保持原值，普通主动消息仍遵守勿扰、夜间、冷却与预算规则。
4. 保留锁屏、离开 / 睡眠、其他来源手动禁止、主动能力关闭、前台请求忙及投递时会话变化的限制。诊断区分 `screen_locked`、`away`、`sleep`、`manual_blocked` 和 `quiet_mode`，不再统一归为 `blocked`。

真实日志复盘使用上面的开关时间及 11 次强制请求记录，调用原版本 `gate` 和修复后的 `gate` 对比：原版本均返回 `blocked`；修复后均清除残留勿扰信号，强制及普通 Beat 可通过该拦截检查。复盘在内存状态中进行，未调用模型、未发送消息、未修改生产数据；时间、夜间和冷却等其他条件仍按各自规则执行，不能据此宣称真实消息已经投递。
