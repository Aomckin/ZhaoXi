# 2026-10-15 过程台词与非最终草稿

## 实际问题

截图对应 2026-10-14 23:35:29 开始的请求 a98572d6-452a-4a24-95c9-2b6f96a85cd7。第一次 Agent 调用返回 738 字的已解码答复，没有工具调用。随后日志记录 required tool call missing; retrying once，下一次 Provider 调用开始前，旧 reveal_process_replies 将这份待采用的最终草稿标成 process，并把公开正文保存到 process_text，传给行动记录卡片。

它并非 LLM 特意生成的长任务台词。旧逻辑尝试发送 model_process，但因超过 180 字而被 too_long 抑制，没有 interim_reply 投递。截图里长篇正文来自行动记录的折叠块。该请求最终为 3 次模型调用、0 次业务工具执行、约 120 秒终止；工具需求判定与该任务的超时需要独立复核。

## 修复

删除行动记录中的非最终正文折叠块，包括旧快照中的 process_text；保留模型、阶段、调用状态、各次/总 Token 和输入构成。Provider 不再保存调用正文，非最终调用仅标为 intermediate；Router 和后台维护正文也不再进入这套记录。没有新增回复前思考展示。

主界面的过程消息继续由既有 interim_reply 事件渲染。只有工具行动同次返回的自然短台词，以及已有明确的进度工具入口，才可进入发送检查；普通回复重试、格式恢复或后台调用不自动变成中途消息。

所有路径统一检查已有耗时门槛，默认 10 秒；最多两句、120 字符，拒绝长篇、标题/清单、协议载荷和未经确认的完成声明。超限候选仅记录抑制原因，不截断正文，不影响工具继续执行或最终回复，不增加模型调用。主模型与 Planner 复用同一份提示，最终回复协议改成明确的无工具调用分支，避免与行动台词混淆。保留原有人格、去重、次数限制与 Planner 的新进展要求。
