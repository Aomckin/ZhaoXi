## 最终实现

- 标准 Agent 的空正文、主回复契约失败、Provider 返回结构或工具协议错误可使用一次纯回复修复。与工具修复共享 `standard_repair_round_limit`，计入真实模型轮数；只有回复修复有一个额外轮数额度。`max_steps`、Provider 调用/Token 上限和请求总超时仍然有效，配置关闭修复时不额外调用。
- 即使已经进入最终收尾或普通模型轮数用尽，只要硬预算仍允许，也可尝试修复。DANGER 使用紧凑原请求、真实工具结果与确认回执，使用现有收尾预算；不申请预算扩展。异常工具调用未执行，不会因修复被重放。
- 已有工具确认进展，后续模型调用仍超过阈值时，运行时自动发送一次简短进度，不依赖模型调用 `emit_interim_reply`。沿用开关、阈值和数量限制；快速调用、无确认进展、已发过中间回复或 Planner 自己管理进度时不补发。消息不落入会话或终止本轮。超时/取消会回收模型调用；通知发送失败不影响最终回复。
- 回复修复失败时保留工具回执和完成事实，回复及整体结果标为失败。`runtime_finished` 和 chat/regenerate 完成、部分完成、失败计数采用业务口径；预算耗尽保持独立分类。已执行操作与回复交付状态分别保留。
- 文本工具协议失败后仅修复说明，不将未执行的后续动作声明为完成；已有操作时保留部分任务状态。

## 验证与边界

本次使用隔离 HTTP 夹具和模拟 Provider，不调用生产模型或写生产数据。覆盖单次/重复协议失败、纯回复工具隔离、修复关闭、DANGER、硬调用/Token 上限、中间回复开关/快速完成/超时取消，以及失败后的会话和决策记录完整性。

单次格式错误可恢复，但无法保证外部模型下一次一定产生正确格式；预算耗尽或第二次失败仍明确保底。正式进程未重启，真实模型日用表现需在加载补丁后复验。

验证结果：全量扫描 1494 项通过、1 项跳过，11 项失败（9 项旧单次调用断言、2 项补修再次返回工具调用的边界）。这些失败均已修正；最终覆盖核心、网关、观测、可靠性、认知、决策和 Agent 集成的 581 项回归全部通过。此前另有 319 项决策/后台/网关验证通过。仅原有 Starlette TestClient 弃用提醒，未调用真实模型。
