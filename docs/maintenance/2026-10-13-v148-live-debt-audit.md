## 其余可靠性债

- **正文交付仍未完全稳定。** 96 条前台终态指标中 response succeeded 84 / failed 12；主回复协议失败事件 17 次，事件数不等于失败请求数。10-13 08:18 请求 `26050e15-0a8a-4b5c-ae5b-f134a6f2abe5` 成功执行 agenda_add，但两轮正文失败。新的协议与有界补修尚不能据此宣称彻底完成。
- **预算和后台结构仍待解决。** 冻结窗口中感知摘要有 17 条调用预算失败及 3 条 ValidationError 待重试。19:31 只读队列为 PROCESSED 614 / FAILED 3 / PENDING 9；3 个失败项均为三次后隔离，PENDING 是新的未尝试记录。这证明失败隔离和后续推进确实生效，不能把尚有失败解释为队首完全卡死。新预算冲突与结构校验根因仍要单独处理。
- **结果分类有正向日用证据。** 上述 08:18 请求实际指标为 task_status=completed、response_status=failed、result_status=failed，正确保留已执行操作；B04 没有继续把正文失败伪装为整体成功。窗口内仍能看到后台失败后前台成功，隔离部分有效，不能扩大为所有组合情形均已验收。
- **QQ 断连噪声确实未清。** 2,361 条 ConnectionRefusedError、2 条 InvalidMessage 警告。本阶段只聚合同类重复警告，保留错误变化、连续次数及恢复记录；连接服务本身是否应启动、退避策略和投递结果未知的处理仍单独待办。
- **停机收尾仍需观察。** 5 条 ERROR 均位于 graceful shutdown exceeded / ASGI 取消附近。不把它们直接视为普通业务失败、历史丢失或恢复成功。

## Phase 2 本次实施

执行项和高风险暂缓项已写入 [Phase 2 计划书](../v1.4.x/Zhaoxi_v1.4.9_Phase2_日用清债计划书.md)。本次中低风险修改：

1. 新投递采用稳定消息 ID；自动同步排除同 Session 已归档的 delivery。旧库分页按真实 delivery_id 去重后再分页，保留首次归档位置、用户消息和原始数据；没有物理删除或回填。
2. 总览与活动历史共用自动门控折叠呈现；失败、完成、无变化和手动结果正常显示，全部原回执可展开追溯，预算、权限和调度不变。
3. User Principles 空有效集合明确提示没有有效摘要，文案不暗示已自动批量更新原文；旧失效历史仍保留。
4. 失败回执保存已有错误码，卡片可兼容读取旧 raw_payload 的安全错误码；调用次数/Token 耗尽具体可见，失败仍是失败。
5. QQ 同类连续连接失败在 1/2/4/8… 次记录聚合警告，错误类型变化立刻记录；连接成功记录恢复并清零，诊断保留失败次数。鉴权、重连间隔、发送和未知结果策略不变。
