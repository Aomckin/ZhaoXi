# 2026-10-14 Dashboard 记忆页

## 原因与实现

记忆导航没有自己的 loader，仅嵌入默认折叠的工程页，所以打开时看不到已有的记忆库和候选。新页直接展示记忆总数/状态分布、活跃簇与未聚类计数、记忆簇主题/摘要/标签/成员数/活跃度，以及当前本地会话最近已完成请求的实际候选。支持簇关键词搜索、活跃/全部/停用筛选，每批显示 20 簇；技术字段折叠查看，原工程检查器按需加载。

新认证接口 /api/dashboard/memory 使用已有 Memory Service 和 Gateway 请求缓存；候选来自本地 session 的响应快照，匹配的最终 trace 可补全指标。不使用 MemoryService.last_retrieval 的全局最近查询，避免后台、QQ 或手动检查器污染。最新请求无候选时明确显示空结果，不回退到此前有候选的请求。重启或缓存淘汰后没有快照，显示暂无记录，不伪造历史。

预取候选增加来源标记；search_memories 工具返回的真实结果也记录到本轮 trace，与预取候选按 ID 合并去重，最多 20 条。这里展示实际注入/返回的候选，而非整个检索候选池或全部排除项。页面 GET 不发起记忆检索，不调用模型/Embedding，也不写激活或维护生产记忆。

## 真实数据验证

通过正式 Core 的只读 /api/debug/runtime 导出已完成 web 请求的 1 条真实候选；SQLite 备份得到当前记忆库副本。隔离预览服务将这份真实请求快照放入现有 Gateway 缓存，使用生产页面代码与新接口渲染，未调用模型或制造模型回复。

浏览器实看结果：1,557 条记忆、33 个活跃簇、15 条未聚类，状态为活跃 167/冷却 1,301/休眠 83/已遗忘 6。当前请求本地预取 1 次、工具检索 0 次，候选正文、簇、评分均显示。点击加载更多显示全部 33 簇；搜索阅读得到 5 簇，无匹配查询正确显示空结果；停用筛选为空；原检查器能展开，浏览器未捕获 error 日志。

私人快照、数据库副本和页面截图仅保存在被忽略的 .pytest_cache/phase3/dashboard-memory；不提交私人正文。工程回归另验证认证、QQ/手动检查器隔离、最新空结果不串用旧记录、工具候选来源与去重。副本页面验证不代表正式 Core 已加载新路由；需要重新加载 Core 后再刷新 Dashboard。
