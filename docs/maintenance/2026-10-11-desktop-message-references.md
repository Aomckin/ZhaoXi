# Desktop 原消息引用补丁

用户反馈：引用需要像 QQ 一样指向原消息，不应把全文复制成输入框里可编辑的文字。替换此前 703f06e 的引用实现，沿用 v1.4.8，不改变图片查看器与独立复制操作。

## 交互与数据

- 右键引用后，输入框上方显示只读引用条：发送者、时间、原文预览 / 图片数量，可取消；输入区只写本次新正文。
- 发出后，引用卡片位于新消息内。点击卡片定位并短暂高亮原消息；原消息尚未加载时回查历史，连续输入合并的消息定位到对应分段。陪伴模式点击引用先展开主窗口。
- 每次合并输入生成稳定消息 ID，服务端保持同一 ID；各输入分段分别携带可选的原消息 ID 和分段索引。刚生成的朝汐回复也补齐 ID，无需刷新即可引用。待发送的消息暂不可作为引用来源。
- 客户端仅提交指针，不提交引用的原文、发送者或原图。Core 在当前会话 / 同会话 SQLite 历史中解析原消息，保存用于界面恢复的只读摘要和指针；持久化正文、附件及 CognitiveEvent 正文仍只有本次新输入。缺失、内部或跨会话来源被明确拒绝；客户端伪造的预览不会覆盖原文。
- 会话恢复、历史翻页和系统消息打开共用渲染路径；重新生成保留原输入及引用身份。旧版已作为普通正文发送的复制引用不自动转换成指针。

## 模型上下文

本轮原消息单独以历史资料注入 STANDARD、FAST 和一次正文修复路径，文本总量限制为 6000 字并标记截断。历史引用的摘要保存在会话与认知流元数据中，后续回顾仍能看懂短正文在回应什么；不增设引用摘要模型调用。

引用图片复用原消息已有媒体，不计作新发送附件，保留原图工具句柄；引用原图与普通历史投影去重，包括 UI 消息 ID 与认知事件 ID 的对应关系。已发送的本地表情只从表情注册服务读取，文件已删除时明确提供图片不可用的事实，不猜视觉内容。后台维护启动时清除前台引用作用域，避免继承引用原图及当前引用语境。
