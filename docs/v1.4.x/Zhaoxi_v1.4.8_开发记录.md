## 逐项交付

| 条目 | 实现与验收 | 仍需核验的边界 |
| --- | --- | --- |
| V148-01 无事可做 | 自动重复跳过按活动/原因聚合，保留计数、最后时间和诊断事件；退避、隔离、关闭的维护不被当作可执行债永久阻塞闲时活动。保留前台抢占和资源上限。 | 真实长期活动分布需观察；可执行维护债的优先级仍生效。 |
| V148-02 决策 | 主模型同轮提供 NEW / CONTINUATION / CORRECTION / EXECUTION / NONE 和自足问题摘要；只有 NEW 且问题有效才登记。schema v4 保存抽象问题、建议和上下文引用，不增加独立模型调用。 | 模型仍可能语义误判，需要真实聊天复验；旧原文标题不自动改写。 |
| V148-03 准则 | 每次读取校验原文来源；缺失/变更项从有效列表及检索退出，放入折叠历史待更新区。原文恢复后自动恢复有效状态；摘要修订历史保留。 | 不猜测新文件替代关系，也不自动删除历史摘要。 |
| V148-04 旧用户消息 | Session schema v4 新增历史归档；可见双角色消息淘汰前保存，分页读取，保留 ID、时间、附件和回复组。模型最近窗口仍有界；仅持久化 request_id、event_id、display_parts 等身份/UI 元数据。 | 已经被旧版本淘汰且无存档的消息未恢复；原截图的所有缺口仍需按原始事件独立核验。 |
| V148-05 中间回复 | 真实进展后的模型轮次提前暴露能力并说明已用时间/阈值；运行时仍拒绝过早、重复或不合格内容，拒绝理由进入诊断。无定时假气泡、无额外等待文案模型。 | 单次模型调用阻塞时不会自行生成中间台词；模型是否合理选用需日用验收。 |
| V148-06 错图 | save_emoji 优先原消息 ID/图片序号的原图引用；latest 限当前触发输入唯一图，拒绝多图歧义和当前无图时偷偷选旧截图。允许明确索引和历史引用，保留来源边界。 | 已删除错误表情不重建；历史日志中的该次错误不因新测试而变成已复现的唯一根因。 |
| V148-07 能力域 | Registry / Manifest 实时聚合能力域；主 Agent、FAST、Planner、Router 调用前读取。工具可自描述用途和边界，新领域无需改生成器。LifeHUD 与物簿在各自工具实现中声明职责。 | 缺少领域元数据时使用实际 group/description；未声明的边界不编造。 |
| V148-08 工作流 | Router 读取真实目录及依赖可用状态，模型路由/降级/旧提示均不能重新选中停用流程。Dashboard 可新增、编辑、启停、移除、查看最近运行；独立管理覆盖文件原子保存，不改安装包，正在执行的定义快照保留。 | 旧两条演示不计日用覆盖；尚无明确业务契约的日用新流程不凭空编造。 |
| V148-09 重生成重复 | 模型调用前复用原用户消息 ID、时间、原触发事件和图片身份；不重新 ingress。相同 request_id 复用缓存结果，已执行工具仍由现有 resume 路径保留。异常也恢复原对话并清理请求上下文。 | 历史消息缺少原始事件身份且找不到事件时不伪造来源。 |
| V148-10 超时 | 直接/恢复 Agent 入口统一 agent_timeout；现有已完成工具结果和仅补回复边界继续生效。 | 上游真实服务错误、网络和业务系统可用性仍需单独排查。 |
| V148-11 归纳 | 明确 disabled / not_due / no_candidates / evaluated / FAILED，不再从时间戳猜成功；保留 Provider/协议错误码、本地部分成果和失败阶段。真实应用失败不提前推进成功检查游标。 | 存储异常仍明确失败并退避，不伪装为无变化。 |
| V148-12 通知 | 主动普通/重要消息和正常回复均接后台通知。窗口前台抑制；逻辑消息去重；1.3 秒轻风铃；Toast 自带声音关闭避免叠音；播放失败不影响可见消息。所有通知点击主窗口，普通回复按消息 ID 定位。 | 原生声音、系统通知权限及实际焦点切换需 Windows 日用复验。 |

## 验收证据

- 全量 Core Python：**1497 通过、1 跳过**（255.26 秒）；仅现有 Starlette TestClient 弃用提示。
- 最终收尾恢复/路由专项：**467 通过**，覆盖额外检查的重生成幂等、异常恢复和停用流程旧提示；与全量范围重叠，不相加。
- 最终发布/记忆/后台专项：**290 通过**；与全量重叠。
- Node 前端：**100 通过、0 失败**。修正旧重试夹具中的 request_id / 目标断言，保留按已接受原输入定位的生产安全语义。
- 物簿：**36 通过、81 子检查通过**；LifeHUD：**33 通过**。与 Core 的工具测试范围有重叠。
- 隔离 Edge 浏览器：**7 项通过**，120 条双角色消息分页、顺序、刷新恢复、回复定位、流程停用持久化与重新启用、无脚本错误。
- 准则管理页兼容浏览器：另外 **7 项通过**，原文读取、摘要修订、查询、刷新和无脚本错误。
- 干净隔离副本构建 Core 1.4.8 与 LifeHUD-Tool 2.0.0 wheel；发布校验、资源/源码一致性记录于 [验收证据](evidence/reliability_v148_acceptance.json)。只允许固定内置风铃资源，其他音频、数据库、秘密及 pycache 继续阻断。最初本地缺 setuptools 和旧构建缓存阻断均保留为构建环境问题，未放宽过滤规则。

验收使用临时数据库、合成消息、假 Provider 和无业务执行的工作流。未调用真实模型、发 QQ 消息、恢复/删除生产表情、重启生产 Core 或写入生产数据库。浏览器测试服务完成后停止。

## 加载与兼容

Core 版本改为 1.4.8，前端 build 标记同步。需退出并重启整个正式朝汐进程，再刷新 Dashboard；这里不把代码提交当作正式实例已经加载。

首次加载后 Session DB 升至 schema v4；旧 schema 数据兼容读取，新增历史不会自动补造旧缺口。需要退回旧 Core 时应恢复升级前数据库备份，旧版本不能直接读取更高 schema。历史容量会随使用增长，模型上下文容量不会随之增长。

新工具领域声明和工作流管理说明见 [动态能力与工作流指南](../guides/tool-domains-and-workflows.md)。
