## 目标与范围

删除已确认的死分支、重复实现和掩盖错误的兜底；修复求职看板备注保存失败造成的假成功。沿用已有模块、诊断字段和测试入口，不引入新依赖、通用状态机、全局缓存或新的配置开关。

| 编号 | 实现任务 | 成功标准 |
| --- | --- | --- |
| V149-01 | 备注保存先确认服务端成功，再更新本地内容、日志与界面 | 网络失败、HTTP 错误及业务失败均保留旧备注并提示错误；成功才展示新备注；取消不请求 |
| V149-02 | 删除内部工具路由的宽泛回退，统一使用确定性路由 | 无效模式及内部实现错误直接暴露；插件可用性探测失败在插件边界记录具体诊断，禁用该工具而不扩大暴露范围 |
| V149-03 | FAST 近期认知不再静默失败 | 可预期的存储/内容错误记录到既有 `last_recent_context.errors` 并写日志；内部编程错误传播；正常空内容不报错 |

## 实现边界

- 模型输出、外部插件、网络、用户输入仍执行边界校验；权限、写入结果不确定性和防重复执行保护保持有效。
- 求职看板只调整实际保存链路，不为一次保存引入请求框架。新增行为验证使用合成数据，不写真实岗位、用户画像或正式数据库。
- 路由调用方一并迁移，更新原先要求无效 mode 静默回退的旧测试契约。
- 合并重试实现时保留现有导入路径，不把 Core 的预算和熔断依赖传递给插件 SDK。
- `web/app.py` 与求职看板整页拆分仅是维护热点，缺少必须全面拆分的证据。本轮以局部修复和减少重复计算处理它们，不把文件行数作为拆分目标。
- 不移除现有 `RuntimeService` 兼容访问，不迁移数据格式，不修改或提交私人数据。

## 验证与交付

1. 针对备注保存失败/成功、路由错误传播与插件探测失败、FAST 存储失败、重试 jitter、动态工具启停运行行为回归。
2. 权限续跑、LoopSafety、回复恢复、FAST、工具控制及重试相关已有回归通过。
3. 运行仓库统一离线测试入口，记录 Core、工具包和 Node 的真实结果；失败定位并修复后继续验证。
4. 检查差异、版本一致性、文档链接及 Git 私人数据忽略规则。
5. 交付任务书、实现、必要回归、开发记录和版本说明。正式进程重启、真实模型/QQ 连接及发布不属于离线验收。

### V149-11 · Router 预测预挂载

复用已提供给 CognitiveRouter 的实时 Tool Domain Map，在同一次 route_cognition 输出中增加 preload_tool_groups（最多四个组）。普通 Agent 首轮预挂载有效且可用的组，避免为已预测能力再花一轮 request_tool_group；诊断显示预挂载组、工具和拒绝项。all、未知组、停用和不可用工具不能挂载。预挂载状态只属于当前请求，权限续跑可沿用；新请求重新判断。预测不构成操作授权，不能绕过 WRITE 确认或造成额外执行。

有现成 Router 调用时同次预测；FAST、图片直达、本地明确路由不为预测新增模型调用，继续使用原确定性挂载。Planner 的业务轮已有全部可用定义，本补丁不另造预测调用；其收尾仍执行 V149-08。工具可用性在真实执行前再次核对；原模型/工具轮数、预算和修复上限保持有效。
