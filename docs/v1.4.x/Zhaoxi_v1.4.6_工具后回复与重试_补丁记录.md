# v1.4.6 工具后回复与重试补丁

开发日期：2026-10-03。2026-10-04 与上一轮[回复交付补丁](Zhaoxi_v1.4.6_回复交付与决策上下文_补丁记录.md)一起整理为本地提交；本次未重启正式实例。

## 实际发生了什么

截图中的请求已经按工具路线进入 STANDARD，并明确要求 `lifehud`。21:17:00，`POST /api/focus/start` 返回 200；21:17:01，`GET /api/focus/current` 返回 200，工具成功记录用时 2.20 秒。随后主模型生成最终回复，10.36 秒后返回 stop、没有新的工具调用；主回复协议收到 81 个字符，去空白后正文长度为零，于是触发 `empty_model_reply`。

因此，实际是工具操作完成、最终台词失败。之前的空回复校验已经生效，但没有在工具成功后接入现有结果回执路径，让界面只显示失败而看不到已完成操作。重试时还有一个独立问题：内部 assistant 工具调用消息被算成用户可见回复，从用户消息发起的重生成被误拒绝为“只能重试当前最后一条未回复消息”。本次只读核验正式日志与会话，没有再开启真实番茄钟。

## 恢复与重试

- 真实工具路径遇到空白、空 reply、仅内部元数据、截断正文或不可解析为可显示内容的表情时，在普通预算尚有余量、未强制收尾的情况下，最多使用一个剩余模型轮次补正文。恢复轮关闭所有工具，不重复写入，不申请额外预算。
- 若恢复仍失败，或已经到收尾 / 模型 / Token 限额，调用现有确认结果回执路径。显示真实已完成、失败或未知操作，保留 `response_status=failed`，不误启动成功后的维护。
- 重生成只把用户消息和用户可见的 assistant 消息视为后续对话；内部、工具草稿与 interim 消息不再误阻塞。旧可见回复、新用户消息、待审批等限制仍保留。
- 显式重生成只用已有结果生成一次最终答复：保留工具结果与 Safety 状态，重置已耗尽的模型轮次，限制为一轮，工具不暴露。避免重试直接因为沿用旧计数而跳过模型。
- 连续失败的可见 notice 使用已有 Session 持久化，重启后仍能作为结果说明供只补回复的重试参考；不把原始工具载荷写入会话库。

本次没有改变 LifeHUD 业务输入或权限，也没有把模型失败假装成正常台词。有效正文遇到错误决策元数据仍沿用上一补丁的容错，不为元数据单独调用修复模型。

## 验证

全量 Python：1247 passed、1 skipped，234.01 秒。随后加入一项回执重启后的重试测试，最终 Core / 网关 / 工具回复专项为 145 passed（4.60 秒），其中本补丁新增 11 项。wheel 299 个源码、插件与静态文件与最终源码逐字节一致，版本 1.4.6。见[验收汇总](evidence/lifehud_v146_reply_recovery_patch.json)。本轮没有前端源码改动；前端验收仍可参照上一补丁，不将旧浏览器结果算成本轮新增验收。

测试使用真实 LifeHUD Tool / Client / LivingIO 实现及 `httpx.MockTransport`，确认 `focus/start` 只 POST 一次并 GET 回读；验证五类不可交付响应、持续失败、额度耗尽、工具失败、从未回复用户发起重试、旧回复拒绝，以及 notice 保存 / 重新加载后的无工具重试。

真实模型验收仅发送合成任务与假工具结果，没有使用本截图或真实前文，也没有请求正式 LifeHUD。测试先用本地 native-call fixture 固定已完成操作，两次后续回复使用当前配置模型；将第一次模型结果替换为 81 个空格后，恢复轮成功交付正文，整个流程只有一个假 `focus/start` 写入和一个回读，耗时 17.27 秒。模型还指出 fixture 标题与合成请求标题不同，没有为了修正标题再启动一个番茄钟。脚本为 [lifehud_reply_live_acceptance.py](../../tests/interfaces/lifehud_reply_live_acceptance.py)，必须手动显式运行。

保留早先探针的限制：模型自行选择合成工具操作时先查询 current、再 start，三轮额度耗尽后注入空正文；得到真实结果回执而没有第四次模型调用，因此“自然回复成功”的断言失败。这次确认了限额回执路径，但不能充当自动补正文成功的证据。后续固定操作的验收单独验证了有额度时的恢复路径。

## 加载与旧轮次边界

需退出并重新启动整个朝汐进程加载。截图这一轮的开启操作已经成功，不应为了补一句回复重新提交开启指令。

旧失败轮次尚未生成持久化 notice，Session 又按既有隐私约束省略内部工具消息；因此重启后仅凭那条用户输入，不能声称旧轮次一定能安全恢复工具结果。本补丁会为以后同类失败保留结果回执并支持只补答复的重试。未对正式会话补造内容，未执行额外业务操作或推送发布。
