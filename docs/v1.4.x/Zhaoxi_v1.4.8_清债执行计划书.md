# Zhaoxi v1.4.8 清债执行计划书

日期：2026-10-10（Asia/Shanghai）。状态：源码开发与隔离验收完成，正式实例待加载与日用复验。依据：[已知问题与清债记录](Zhaoxi_v1.4.8_Reliability_已知问题与清债记录.md)、[三天日志审计](../maintenance/2026-10-10-three-day-failure-log-audit.md)。用户已授权从只读登记转入实现；逐项记录代码、隔离验收和日用加载的不同状态。

## 目标与实施边界

让失败有准确解释，后台没有工作时安静退出，用户消息和图片身份可追溯，模型首次调用前理解能力领域，长任务能表达真实进展，后台回复可靠通知。修复过程保留既有权限、写入幂等和前台抢占；不盲重放已完成操作，不猜造旧用户消息，不以关键词路由或固定工具清单代替语义判断。

生产资料和数据库保持完整。开发验收优先临时数据库、合成消息、假 Provider 和隔离浏览器；不为测试向 QQ 发消息，不重启生产实例。需要实际运行环境才能证明的结论保留明确待验收状态。视觉规划继续延期。本计划不将未知根因自动认定为已修复。

## 具体约束

- 决策问题摘要来自本轮主模型结合上下文的抽象；不增加独立分类 / 摘要模型调用。兼容旧记录，但旧原文标题不当作新标准或高可信学习证据。
- 动态 Tool Domain Map 以 Registry / Manifest 和插件元数据为事实源；不维护固定工具名到领域映射，不固定四领域。缺元数据时展示实际工具描述并标明边界未知，不宣称未注册能力。
- 工作流优先修补动态发现、管理和执行证据。日用业务流程必须有明确任务价值和工具契约，不凭空凑流程；尚缺用户具体业务需求的覆盖范围如实登记。
- 历史分页保留角色、消息 ID、时间、附件和回复组；模型仍使用有界最近窗口。已有永久缺口不靠助手回复推造原话；可能恢复来源须单独验证。
- 中间回复继续由模型根据真实进展选择，不恢复此前取消的定时假气泡，不单独调用模型制造等待文案。
- 通知在可交付时检查窗口焦点；新回复每逻辑消息一次，不对 token、SSE 重播、历史恢复响铃。点击任何通知都激活主窗口；通知出现本身不抢焦点。
