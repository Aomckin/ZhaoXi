# Zhaoxi · Sunflower Garden 未来计划
## Deferred Visual Roadmap / 视觉债延期记录

> 状态：**延期，不进入当前主开发线**
>
> 原计划：v1.4.8 Sunflower Garden\
> 当前处理：**保留概念，不继续施工**

## 1. 为什么延期

当前视觉债不影响主要功能，而稳定性、报错、超时、卡住不回复等 Reliability 债会直接影响日常使用。

因此当前优先级调整为：

```text
稳定可用
>
主要功能
>
体验细化
>
视觉装修
```

Sunflower Garden 暂时封存方向，不继续消耗开发精力。

## 2. 最终视觉方向仍然保留

未来目标不是“向日葵主题皮肤”，而是：

> **朝汐真正拥有一个窗边小屋。**

空间关系：

```text
房间内部
├─ 暖白 / 奶油色墙面
├─ 大木窗
│  └─ 窗外：天空 + 向日葵花海
├─ 窗台
│  └─ 小花 / 少量装饰
└─ 前景浅木桌
   ├─ 输入区
   ├─ 蜡烛
   └─ 少量桌面物件
```

核心语义：

```text
聊天区 = 窗
桌面 = 前景实体
窗外 = 花海
页面外围 = 房间
装饰物必须“落在空间里”
```

## 3. 已确认的空间参考

未来重新开发时优先保留这些关系：

```text
大窗占主要视觉面积
厚木窗框
窗台存在感明确
前景桌面靠窗
室内暖、室外亮
桌上物件有真实落点
背景风景只存在于窗户内部
```

明确避免：

```text
全屏花海壁纸
+
巨大半透明聊天面板
+
底部木纹矩形
+
悬浮装饰图标
```

## 4. 保留的视觉元素

未来仍可考虑：

```text
向日葵花海
浅木桌
大木窗
窗帘
蜡烛
小向日葵 / 盆栽
暖白室内
浅蓝天空
少量生活小物
```

原则：

> **少而有位置。**

## 5. 三时段场景保留

未来可以继续做：

```text
DAY
DUSK
NIGHT
```

第一版只根据本地时间切换。

### DAY

```text
浅蓝天空
明亮花海
自然日光
暖白房间
```

### DUSK

```text
金色夕照
偏暖室内
花海变金
```

### NIGHT

```text
深蓝窗外
暖黄室内
蜡烛成为主要暖光点
```

设计原则：

> **时间只改变房间的光。**

暂不扩展：

```text
天气
季节
实时日出日落
位置
```

## 6. 轻交互候选

空间骨架成立后再考虑：

```text
蜡烛 ON / OFF
窗帘 OPEN / HALF
窗外极轻微动态
```

必须：

```text
纯前端
低性能开销
不依赖 Core
不影响主要功能
```

## 7. 重新启动 Sunflower Garden 的前置条件

至少满足：

```text
1. 朝汐主要功能进入稳定日用状态
2. Reliability 债明显下降
3. 日常聊天很少再卡住 / 报错 / 无回复
4. 有明确空间草图或参考图
5. 能画清窗、桌、房间、UI 的位置关系
6. 愿意接受至少 2~3 轮截图迭代
```

## 8. 未来正确开发顺序

### Phase 0 · 先画空间

先确定：

```text
窗在哪
多大
桌在哪
多高
房间墙面露多少
聊天内容在哪一层
输入框属于桌还是窗
装饰物落在哪里
```

颜色可以暂时不管。

### Phase 1 · 只做白天空间骨架

只实现：

```text
房间
窗
桌
聊天区域
输入区域
```

不做黄昏、夜晚、蜡烛和动画。

先确认：

> **空间关系本身是否成立。**

### Phase 2 · 统一视觉语言

再处理：

```text
颜色
圆角
阴影
木色
暖白
字体层级
卡片语言
```

### Phase 3 · 三时段

接入：

```text
DAY
DUSK
NIGHT
```

### Phase 4 · 轻交互

最后再增加：

```text
蜡烛
窗帘
轻微环境动画
```

### Phase 5 · Dashboard 统一

Dashboard 只继承：

```text
Design Tokens
卡片
按钮
圆角
色彩语言
```

不做成场景页。

## 9. 未来开发原则

必须坚持：

> **先空间，后美术。**

> **先白天，后三时段。**

> **先静态成立，再加交互。**

> **Codex 负责施工，不负责自由设计空间。**

## 10. 推荐迭代方式

未来最适合：

```text
草图 / 参考图
↓
实现一个小版本
↓
截图
↓
人工挑刺
↓
修改
↓
再截图
```

不要再只给：

```text
“做成窗边花海风格”
```

这类抽象要求。

## 11. 当前主线优先级

Sunflower Garden 暂停后，v1.4.x 后续优先偿还：

```text
Reliability 债
Graceful Degradation
Provider / Tool 报错
超时
无回复
后台任务故障隔离
状态污染
失败恢复
长期运行稳定性
```

原则：

> **先让朝汐稳定地活着，再装修她的房间。**

## 12. 版本号处理

Sunflower Garden 不必占用当前下一个版本号。

可以：

```text
保留名称：
Sunflower Garden

版本号：
未来恢复开发时再决定
```

因此后续 v1.4.x 可以继续用于 Reliability / Cleanup 等主线。

## 13. 现有材料保留

建议保留：

```text
Sunflower Garden 视觉概念草案
轻量开发任务书
第一次失败截图
空间参考图
后续草图
```

第一次失败版本尤其有价值，因为它证明：

```text
“元素都在”
不等于
“空间成立”
```

## 14. 最终完成标准

未来真正完成时，不应只是“更漂亮”，而应该让人自然感受到：

> **这是朝汐的小屋。**

打开界面时能清楚感知：

```text
我在房间里
前面是一张桌
桌后是一扇窗
窗外有花海
朝汐就在这里陪我
```

如果这个空间关系没有成立，就不算完成。

## 15. 一句话总结

> **Sunflower Garden 暂时不还。**
>
> **方向保存，参考保存，失败经验也保存。**
>
> **等朝汐先把可靠性和日用体验打磨稳，再回来认真给她装修房间。**
