# Zhaoxi v1.4.x · Sunflower Garden
## 视觉概念草案

> 项目：**Zhaoxi / 朝汐**\
> 版本：**v1.4.x**（具体补丁版本待定）\
> 类型：**Visual Concept Draft / Frontend Aesthetic Direction / Spatial UI**
>
> 实施安排：**留到 v1.4 系列最后统一收口前端。** 先完成该系列其他功能；本任务暂缓，不作为下一补丁版本的开发任务。
>
> 核心主题：
>
> > **把“朝汐的小桌边”真正做成一个可以长期停留、带有陪伴感与空间感的地方。**
>
> v1.4.x 不优先处理 Agent 核心逻辑，不优先新增复杂能力，而是集中偿还：
>
> ```text
> 视觉风格债
> 空间感缺失的债
> 前端界面“像不同版本焊起来”的债
> 工程面板侵入生活界面的债
> 缺少统一设计语言的债
> ```
>
> 它的目标不是单纯“换一个黄色主题”，而是让朝汐当前的桌面应用：
>
> - 从普通应用界面，变成**朝汐真实生活着的小空间**；
> - 从功能拼接，变成**统一的向日葵世界观视觉语言**；
> - 从静态背景，变成**能随时间轻微呼吸变化的窗边房间**；
> - 从“界面能用”，提升到“界面本身就有陪伴感”。

---

# 0. 一句话概念

> **朝汐坐在一张浅木小桌边陪你。中间的大聊天区像一扇室内窗，窗内是你和她的对话，窗外是阳光下的向日葵花海与天空；房间里有木桌、便签、小装饰、柔和光照与少量轻交互，让整个界面像一间真的被她使用着的小屋。**

---

# 1. 本版定位

v1.4.x 的关键词不是：

```text
重构
新能力
复杂动画
大规模逻辑改造
```

而是：

```text
统一
收束
气质
空间
陪伴感
```

因此：

```text
保留当前主界面结构
保留功能布局大体方向
优先改“气质”与“空间感”
谨慎加入少量轻交互
```

---

# 2. 总体方向

Sunflower Garden 不是简单的“向日葵皮肤”。

它应同时包含三层意义：

## 2.1 向日葵

象征：

```text
温暖
生命感
朝向光
朝汐的世界观元素
```

---

## 2.2 小桌边

象征：

```text
陪伴
贴近
生活
不是远处的助手，而是在桌边的存在
```

---

## 2.3 房间与窗户

象征：

```text
空间感
居住感
朝汐真的“在这里”
窗外世界与窗内陪伴同时存在
```

---

# 3. 视觉空间模型

本版建议将主界面理解为一个四层空间：

```text
① 房间底层（Room Layer）
② 窗户主舞台（Window Layer）
③ 桌面功能层（Desk Layer）
④ 装饰与轻交互层（Life Layer）
```

---

# 4. 房间底层（Room Layer）

这是最底下的空间背景。

负责表达：

```text
这里是朝汐的小房间 / 小桌边
```

建议元素：

```text
暖白 / 奶油黄墙面
柔和室内光
浅木色基底
极淡纹理
空气感
```

注意：

```text
不能像写实 3D 场景
不能细节太满
不能抢 UI
```

它只是：

```text
房间的“气”
```

---

# 5. 窗户主舞台（Window Layer）

这是整个界面的核心。

当前大聊天区建议被重新理解为：

> **一扇室内大窗。**

也就是：

```text
聊天窗口 ≠ 普通白色面板
聊天窗口 = 朝汐小屋里的一扇大窗
```

这层承担：

```text
聊天消息
对话主舞台
窗内 / 窗外关系
```

---

# 6. 窗户层的视觉目标

它应该同时具有：

```text
大面积承载内容的能力
轻微玻璃感
浅木 / 白木窗框感
柔和圆角
半透明暖白内层
低视觉噪音
```

它不是：

```text
毛玻璃系统面板
海报展示框
普通 IM 聊天白板
```

---

# 7. 窗外世界（Exterior View）

窗外不是纯背景图，而是整个空间叙事的重要部分。

建议为：

```text
大片柔和向日葵花海
浅蓝天空
少量白云
开阔远景
自然光
```

重点：

```text
花海应主要位于远处 / 中远景
不要扑到前景
不要贴脸式高细节花朵
```

---

# 8. 窗内世界（Interior Feeling）

窗内是朝汐与你对话的空间。

它更强调：

```text
桌边
木头
房间
便签
生活小物
暖光
安静
```

这意味着：

```text
向日葵世界不是只有“花海”
还要有“有人在这里生活”的痕迹
```

---

# 9. 桌面功能层（Desk Layer）

“小桌边”应该名副其实。

功能元素不应只是简单排版块，而是尽可能像：

> **摆在桌上的物件。**

例如：

```text
角色信息卡 → 像桌边立牌
今日主线 / Agenda → 像便签卡片
输入框 → 像桌面留言条 / 对话台
一些功能入口 → 像桌上小物件 / 小卡片
```

---

# 10. 装饰与轻交互层（Life Layer）

这一层不承担主要功能。

它的作用是：

```text
让空间看起来“活着”
```

包括：

```text
小向日葵 / 盆栽
窗帘边角
光影
小挂件
蜡烛
桌面装饰
微小 hover 反馈
少量轻动态
```

---

# 11. 本版主视觉方向

最终方向确定为：

> **窗边花海版**

这比纯“花海壁纸版”更适合桌面应用。

原因：

```text
更有空间感
更适合长期使用
更能兼容 UI 覆盖
更符合“小桌边”的居住感
比全屏风景图更自然
```

---

# 12. 主视觉不是宣传海报

Sunflower Garden 的主视觉图必须明确定位为：

```text
软件界面背景
```

而不是：

```text
角色插画海报
风景大图
宣传横幅
```

因此它应满足：

```text
中间大面积干净区域
低对比
低细节噪音
易覆盖 UI
不放文字
不放复杂主体
```

---

# 13. 主界面空间构图建议

大致关系建议：

```text
左上：朝汐角色信息 / Presence 卡
中间：大聊天窗
右侧：小桌边控制 / 附属面板
底部：输入区
背景：房间 + 窗外花海
```

在保留当前结构的前提下：

```text
聊天窗更大
桌边感更强
背景空间感更完整
```

---

# 14. 聊天窗放大

用户希望：

```text
聊天窗口放大些
```

这是对的。

因为在 Sunflower Garden 里：

```text
聊天窗 = 房间里最重要的窗户 / 主舞台
```

它应该更明显、更舒展、更像真正“坐在窗边说话”的区域。

---

# 15. 聊天窗外观建议

推荐特征：

```text
大圆角
浅木 / 暖白窗框感
轻微内阴影
轻微玻璃感
内部为暖白 / 极淡米白
消息区域留白更大
```

不建议：

```text
纯白死板大面板
重阴影悬浮卡
太科技风玻璃
```

---

# 16. 左上朝汐信息卡

当前左上人物信息卡可以继续保留，但应更像：

```text
桌上的小立牌 / 小卡片
```

建议：

```text
圆角更统一
背景更柔和
头像与向日葵世界融合
Presence 更像小标签
整体更轻
```

目标：

```text
从“状态面板”
变成“朝汐的小桌牌”
```

---

# 17. 右侧“小桌边”面板

右侧控制面板应保留，但视觉上要更克制。

它不是主舞台，而是：

```text
桌边的附属区域
小抽屉 / 侧边台面
```

因此它应该：

```text
比中间聊天窗更安静
层级更低
颜色更淡
边界更柔和
不抢主题
```

特别是：

```text
工程调试元素不应显得像独立后台系统
```

而应尽量纳入同一视觉语言。

---

# 18. 输入区定位

底部输入区建议像：

```text
桌面留言条
书写区
对话纸条
```

应更宽、更稳、更柔和。

建议：

```text
浅暖白背景
柔和阴影
适度圆角
左右留白更自然
发送按钮更像桌边小控件
```

---

# 19. 木桌概念

“小桌边真的做成木桌的样子”这一点成立。

但木桌感要：

```text
浅木
克制
低对比纹理
不抢内容
```

木桌不应变成：

```text
高清木纹壁纸
家具展示页
```

它只是：

```text
空间叙事锚点
```

---

# 20. 推荐色彩方向

建议总色系：

```text
向日葵黄
暖白 / 奶油白
天空浅蓝
浅木色
少量浅棕
极少量叶绿
深灰褐文字色
```

整体倾向：

```text
暖、明、轻、柔和
```

避免：

```text
饱和黄过多
高对比棕色
过脏的复古黄
过冷的科技蓝
```

---

# 21. 设计语言关键词

可以统一为：

```text
明亮午后
窗边
花海
浅木
暖白
呼吸感
生活感
陪伴
克制可爱
柔和而不甜腻
```

---

# 22. 气质目标

它不是：

```text
二次元宣传页
极简生产力工具
花里胡哨主题皮肤
```

它应该更像：

> **一间有人居住、安静、温暖、会陪伴你的桌边小屋。**

---

# 23. 装饰元素（建议）

可加入的装饰元素：

```text
小向日葵
小盆栽
窗帘边角
便签
小纸卡
柔和光斑
小挂饰
木边框细节
蜡烛
```

原则：

```text
少而准
强化空间
不抢功能
```

---

# 24. 窗帘元素

建议轻量加入窗帘。

原因：

```text
会大幅强化“窗户”成立感
能帮助白天 / 黄昏 / 夜晚场景切换
可成为纯前端轻交互元素之一
```

窗帘应：

```text
轻
柔
边角点到为止
不把窗遮满
```

---

# 25. 蜡烛元素

用户已将台灯构想替换为：

> **蜡烛**

这是很好的选择。

蜡烛比台灯更符合：

```text
小桌边
温暖
陪伴感
夜晚氛围
轻微互动
```

蜡烛可作为：

```text
夜晚场景中的暖光元素
纯前端轻交互元素
桌边装饰
```

---

# 26. 蜡烛的视觉角色

蜡烛在三时段中可承担不同存在感：

## 白天

```text
存在，但不显眼
```

## 黄昏

```text
可微微发光 / 准备点亮
```

## 夜晚

```text
成为房间里的重要暖光锚点
```

---

# 27. 轻交互候选 1：蜡烛

推荐作为本版的第一轻交互。

交互建议：

```text
点击蜡烛
→ 点亮 / 熄灭
```

效果：

```text
局部暖光变化
蜡烛火苗轻微晃动
夜晚氛围增强
```

注意：

```text
只影响前端视觉
不影响 Core
可本地保存状态
```

---

# 28. 轻交互候选 2：窗帘

推荐作为本版第二轻交互。

交互建议：

```text
点击 / 拖动窗帘区域
→ 打开一些 / 收拢一些
```

第一版只需少量状态：

```text
OPEN
HALF
```

即可。

注意：

```text
无需复杂拖拽系统
无需真实物理模拟
```

---

# 29. 轻交互候选 3：窗外微动（非直接交互）

虽然不一定可点击，但建议作为生命感来源。

包括：

```text
云极慢移动
花海轻微起伏
光感轻微变化
```

要求：

```text
极轻
极慢
近乎背景呼吸
```

绝不能做成：

```text
动态壁纸炫技
```

---

# 30. 三时段场景机

这是用户新增的重要构想。

建议作为 v1.4.x 的正式视觉能力之一：

> **场景随时间变化，但只做最简单的三态：白天 / 黄昏 / 夜晚。**

---

# 31. 三时段的目标

它的意义不是“天气系统”，而是：

> **让房间的光跟着时间变。**

也就是：

```text
时间变化
→ 房间氛围变化
→ 朝汐的小桌边更像真实空间
```

---

# 32. 第一版时间模式

只做：

```text
DAY
DUSK
NIGHT
```

时间段可先粗略：

```text
06:00–17:00  DAY
17:00–19:00  DUSK
19:00–06:00  NIGHT
```

后续可调。

---

# 33. DAY · 白天

白天是标准状态。

建议表现：

```text
浅蓝天空
白云
明亮向日葵花海
自然日光
暖白室内
浅木桌面
花海颜色最鲜活
整体最清新
```

---

# 34. DUSK · 黄昏

黄昏是氛围最强状态。

建议表现：

```text
暖橙金色天空
夕阳感
向日葵偏金色
远处可带一点淡粉 / 淡紫
室内整体更暖
卡片边缘带夕照感
阴影稍拉长
```

黄昏应带来：

```text
放学后 / 傍晚回到桌边的感觉
```

---

# 35. NIGHT · 夜晚

夜晚不应只是“暗色模式”。

建议表现为：

```text
深蓝夜空
少量星星
花海变成暗色轮廓
室内暖光亮起
木桌仍然温暖
蜡烛成为暖光锚点
窗玻璃可有极淡反光
```

目标：

> **天黑了，所以朝汐把房间里的光留给你。**

---

# 36. 时间场景的技术原则

第一版时间变化：

```text
只基于本地时间
不接天气 API
不接地理位置
不做精确日出日落
```

---

# 37. Debug / 手动切换

为了方便测试与验收，应允许：

```text
强制白天
强制黄昏
强制夜晚
恢复自动
```

便于：

```text
设计调试
截图验收
录制展示
```

---

# 38. 时间变化是“房间的光在变”

这应成为本版的设计原则之一：

> **时间只改变房间的光。**

而不是：

```text
搞成天气系统
搞成自然模拟器
搞成复杂环境引擎
```

---

# 39. 技术实现方向（概念级）

推荐：

```text
scene = day / dusk / night
```

并让前端根据场景切换：

```text
背景主视觉
色彩 token
阴影
高光
蜡烛表现
窗外表现
```

也就是：

```text
同一结构
不同视觉状态
```

---

# 40. 背景策略

不建议“整站一张固定大图”。

更适合：

```text
全局基础背景 = 轻
主视觉背景 = 小桌主界面使用
装饰元素 = 局部轻加
```

也就是：

## 40.1 全局底色

```text
暖白 / 奶油色渐变
浅蓝空气感
轻纹理
```

## 40.2 小桌主视觉

用于：

```text
主桌面
首页
主要对话界面
```

可使用：

```text
窗边花海主视觉
```

## 40.3 Dashboard / 工程层

只继承：

```text
色彩语言
圆角
阴影
组件风格
```

不要完整继承：

```text
重主视觉背景
花海大图
强场景化装饰
```

---

# 41. Dashboard 视觉原则

Dashboard 应保持：

```text
更平整
更克制
更干净
更像控制台
```

但不应完全脱离 Sunflower Garden。

它应像：

```text
同一房间里的抽屉 / 台面
```

而不是：

```text
隔壁另一个系统
```

---

# 42. 组件统一原则

Sunflower Garden 还需要统一：

```text
圆角
阴影
留白
按钮层级
标签样式
卡片样式
状态反馈
空状态
加载态
错误态
```

这部分比“背景图”更重要。

---

# 43. 卡片语言

建议卡片统一为：

```text
暖白 / 奶油白
轻阴影
较大圆角
留白舒展
边缘柔和
```

不同层级通过：

```text
透明度
边框
阴影强弱
```

区分，而不是靠：

```text
五花八门的背景色
```

---

# 44. 按钮语言

按钮应更像：

```text
桌边的小控件
```

而不是传统后台按钮。

建议：

```text
主按钮 = 柔和向日葵黄
次按钮 = 暖白 / 浅木边框
危险按钮 = 克制暖红，不要刺眼
```

---

# 45. 状态反馈语言

行为反馈建议更“生活化”。

例如：

```text
🌱 整理完成
📖 回顾完成
🐾 正在休息
🕯 蜡烛已点亮
🌇 已切换到黄昏
```

比单纯：

```text
SUCCESS
OK
DONE
```

更符合朝汐气质。

---

# 46. 空状态

空状态也应融入 Sunflower Garden。

例如：

```text
没有近期状态时
没有记录时
没有活动时
没有消息时
```

都不应该只是空白框。

可以有：

```text
轻文案
小装饰
淡场景感
```

---

# 47. 加载态

加载态应减少科技味。

可以更像：

```text
轻呼吸
光点
小太阳 / 小花 / 小足迹式节奏
```

而不是：

```text
传统后台 spin loader
```

---

# 48. 错误态

错误态也应克制。

原则：

```text
人类可读
温和
不惊吓
可恢复
```

例如：

```text
“这次窗外风有点大……刚刚没拿到结果，等会再试试。”
```

或更简洁的人类反馈。

---

# 49. 本版不做什么

必须明确限制范围。

v1.4.x 不做：

```text
不重构 Agent Core
不重构 Memory
不重构 Decision
不新增复杂功能系统
不做手机端
不做实时天气
不做地理位置
不做复杂动态壁纸
不做大规模可拖拽物件系统
不做小游戏
不做房间经营玩法
不把 Dashboard 变成场景页
```

---

# 50. 为什么要克制

Sunflower Garden 的危险在于：

```text
很容易从“漂亮的小桌边”
膨胀成“什么都想往房间里塞”
```

所以第一版必须坚持：

> **先做“成立的空间感”，不要做“内容过量的房间模拟器”。**

---

# 51. 本版的真正目标

最终想实现的，不是：

```text
我做了一个向日葵主题 UI
```

而是：

> **打开朝汐时，像真的来到她的小桌边。**

你能看到：

- 她的小桌
- 她的窗
- 窗外的花海
- 房间里的光
- 晚上点着的蜡烛
- 白天与黄昏的不同空气

然后在这里和她说话。

---

# 52. 视觉参考抽象

如果要指导后续画主视觉 / 提取风格，可抽象为：

```text
窗边
明亮午后
暖白房间
浅木桌面
向日葵花海
淡蓝天空
少量白云
生活感物件
低视觉噪音
适合软件覆盖
```

---

# 53. 主视觉提示词方向（概念）

后续若要生成主视觉，可沿以下概念：

> **朝汐桌面应用主界面背景，窗边花海版。明亮温暖的午后室内场景，靠窗视角，窗外远处是大片柔和的向日葵花海与浅蓝天空。室内为暖白与浅木色调，生活感轻微，整体清新、安静、有陪伴感。画面中间保留大面积干净低细节区域供聊天 UI 覆盖，左上区域适合放角色信息卡，右侧适合浅色侧栏叠加。整体是软件背景，不是海报，不要复杂主体，不要过强对比，不要文字。**

这部分是视觉母体，而不是最终实现本身。

---

# 54. 适合先做的最小成果

本版建议先做出一个可运行的最小 Sunflower Garden：

```text
1. 主背景改成“房间 + 窗外花海”空间关系
2. 聊天区做成窗户感
3. 左上角色信息卡重做成桌边立牌感
4. 底部输入区重做成桌面留言条感
5. 统一基础 token（颜色 / 圆角 / 阴影 / 间距）
6. 接入 DAY / DUSK / NIGHT 三态
7. 做两个轻交互：蜡烛、窗帘
8. 让窗外有极轻微生命感
```

这样已经足以成立。

---

# 55. 轻交互优先级

推荐优先级：

## P0 必做

```text
蜡烛点亮 / 熄灭
```

## P1 推荐

```text
窗帘开合（简状态）
```

## P2 可选

```text
窗外微动
```

# 56. 生命周期想象

白天：

```text
窗外是明亮花海，房间轻快，蜡烛安静放着。
```

黄昏：

```text
花海和天空变暖，房间像被夕阳照着。
```

夜晚：

```text
外面暗下去，房间里的光和蜡烛留下来。
```

这种节律感，本身就是朝汐 Presence 的一部分。

---

# 57. 与“朝汐的小桌边”概念的关系

Sunflower Garden 并不是重新定义新产品。

它只是把原本已经存在的“小桌边”理念真正做实。

也就是让：

```text
“小桌边”
```

从一个命名，变成一个具体且可感知的空间体验。

# 58. 对后续版本的意义

Sunflower Garden 不只是好看。

它还会给后续版本铺路：

```text
Reliability 版本
→ 在更完整的界面骨架中补稳定性

未来手机端
→ 可以继承已成熟的视觉语言

未来更多 Presence / Activity 展示
→ 已有统一空间可挂载

未来更强的角色感
→ 有了固定“生活空间”
```
